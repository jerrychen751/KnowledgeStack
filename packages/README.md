Monorepo architecture allows multiple packages (folders with package.json file) to live in the same git repository. Packages in the same repo can depend on each other without being published to the public npm registry.

Contains code where the two separate deployable things, which is the web app and the API NestJS backend, when they need the identical code and the code can run in every environment that imports it. For example, types would be shared but database access is not, because the web should call the API and the API should talk to the database. So the database code has exactly one consumer, which is apps/api. Another example is a small subset of shared utils. It needs to be a pure function, and both sides need to import and use exactly the same thing. And all of these utils should start in an individual location and only be refactored into shared when there is genuinely a need. So don't do it beforehand. Only do it when it's needed.

Has one shared file for each public API domain: `shared/src/auth.ts`, `chat.ts`, `sources.ts` and `workspaces.ts`. Plus one `http.ts` for the status and error bodies that every domain answers with, because /health answers only those. Each file holds the request and response shapes of its routes and nothing else, and every timestamp in it is an ISO 8601 string, which is what JSON carries.
